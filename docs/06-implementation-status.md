平台行为发现（影响验收口径，详见第 4 节）：该资源所在 CDN 对携带自洽认证头的请求未校验头内容——篡改 `access_token` 或 `mac_key` 后仍返回 200。因此“服务器拒绝无效凭据”无法在该资源上真实触发，相关错误分类由离线契约测试覆盖；无凭据时的 401 拒绝路径已在真实平台验证。

## 3. 待验证范围

以下事项需要其他平台或人工检查，**当前均为“待验证”**，不得据此宣称全面验收：

- Windows、Linux 安装运行，无 `DISPLAY` 环境，三平台 keyring 原生后端实测。
- Windows 控制台的 Ctrl+C 中断行为（macOS 已以 SIGINT 验证，信号语义不等价）。
- 中文路径、长文件名与大小写冲突的人工核对（自动化已覆盖模拟路径）。
- 服务器端拒绝无效凭据的真实表现：平台对该类教材资源认证宽松（见第 4 节），无法在真实平台触发；401/403/400 的分类与“不统一说成 Token 过期”由离线契约测试覆盖。
- 对其他资源类型或权限更严格的资源的凭据行为（如教师专属资源）。

真实平台验收的记录格式见[测试与验收](05-testing.md)第 6 节；补充记录时追加到第 2 节并注明日期与版本。

## 4. 已知限制

- 平台 `ti_md5` 可能是非标准值（实测出现 `…-3` 后缀）或缺失；此时只校验大小与 PDF 头，并记录本地 SHA-256，不虚报平台摘要校验通过。
- 同一资源可能同时提供 PDF 源文件与逐页图片包、缩略图、`ebook_mapping` 映射；适配器只选择 PDF 源文件，图片包不计入 artifact。
- 实测平台私有 CDN 对携带自洽 `X-ND-AUTH` 头的请求不校验头内容（篡改 token/mac_key 仍放行），仅在缺失认证头时返回 401。认证强度由平台决定；本工具不提供绕过认证的承诺，也不能把“下载成功”解读为凭据已被平台确认有效。
- 无平台修订或摘要可比时，跳过行为会附带“平台内容版本未确认”警告，不宣称本地是最新版。
- Chrome 本地存储中同一凭据存在多条不同 `diff` 的记录；导入已按数据库、键和写入序号还原最新状态，同一浏览器配置内取最新记录，多个浏览器配置都有记录时由用户选择来源。
- 文件锁、原子发布与独占创建仅面向本地文件系统；网络共享盘不做承诺。
- `contract` pytest 标记用于单元与契约层（无网络样本测试）；`live` 标记保留给显式启用的真实平台检查，默认测试始终排除它。
