# 开发计划

本文用于组织新项目的实现与验收。**当前处于设计阶段，本文中的新项目模块、命令和检查均尚未实现。** 暂定项目名为 `textbook-cli`，Python 包名为 `textbook_cli`，命令名为 `textbook`。

## 1. 目标与实现顺序

首版交付一个在 Windows、macOS、Linux 终端内运行的电子教材 PDF 下载工具，支持筛选选书、多选、凭据导入、下载进度、取消、失败重试，以及有依据的完整性检查和去重。先建立可离线验证的核心，再接入交互界面，最后验证安装与真实平台访问。

采用 Python 3.10+。基础依赖为 requests、Typer、prompt_toolkit、Rich、platformdirs、keyring、filelock；pypdf 用于可选 PDF 书签，标准库 SQLite 保存下载清单。核心不得依赖 Tkinter、PIL、psutil、sv-ttk 或 pywin32。元数据访问统一经过平台适配器，终端输出统一交给 renderer。

首版不包含配套音频、课程资源、自动登录、凭据自动刷新、Range 续传和跨次任务恢复。下载清单服务于验证与去重，不承担恢复未完成任务的职责。

## 2. 分阶段交付

### P0：项目骨架与来源记录

交付：

- 创建独立项目、Python 包、开发依赖与命令入口，不修改参考项目作为实现路径。
- 建立核心、平台适配器、存储、CLI 和 renderer 的边界；核心通过结构化结果与事件暴露状态。
- 建立测试目录、离线样本目录和 Windows/macOS/Linux 的 CI 配置。
- 记录参考仓库及使用的提交；对复制或实质改编的代码保留原版权与 MIT 许可文字，记录改编范围。教材内容不作为软件许可的一部分。
- 确定退出码、错误类别、配置位置与日志脱敏规则，锁定并记录依赖版本。

完成门槛：

1. Python 3.10 环境能够安装项目并查看帮助；此时尚不要求真实下载。
2. 导入核心不会创建窗口、读取凭据、发出网络请求或产生终端输出。
3. 包依赖和导入路径不包含上述 GUI 依赖；代码来源与许可证可追溯。
4. CI 可运行离线检查，且测试默认不访问真实平台。

### P1：平台适配器、目录与凭据

交付：

- 将平台目录、分类标签、索引分片、教材详情与 PDF 文件条目转换为稳定的内部模型。
- 将平台字段变化、网络错误、无可用 PDF 等情况转换为明确错误，避免以空列表掩盖故障。
- 实现目录缓存：TTL 为 24 小时，支持显式刷新；更新失败可使用可读的旧缓存，并显示缓存时间和过期状态。
- 实现 `access_token`、`mac_key`、`diff` 三字段校验、导入、状态查看与清除；默认保存在系统 keyring。
- keyring 不可用、被锁定或拒绝访问时明确失败，不静默改存明文；不在日志或错误中输出秘密。
- 下载可通过 `--credentials-file FILE` 使用仅保留在本命令内存中的三字段 UTF-8 JSON，优先于 keyring；向导可明确选择“仅本次使用”。持久导入命令仍要求 keyring 可用。
- 建立统一 HTTP 客户端：连接/读取超时为 10/60 秒，区分 400、401/403、404、429、5xx 和网络故障。

完成门槛：

1. 离线契约样本覆盖正常目录、多个分片、缺失可选字段、错误结构和无 PDF 详情。
2. 分类与筛选结果可追溯到资源 ID；同名教材与不同版本可区分。
3. 缓存命中、过期、显式刷新、损坏、更新失败与旧缓存降级全部可测；首次获取失败且无缓存时明确报错。
4. 凭据导入、清除、存储失败、临时文件凭据优先级、MAC 签名和秘密脱敏通过离线测试；临时凭据不写入配置或下载清单。
5. 错误不被误判：400 不直接等同凭据过期，401/403 不通过切换 CDN 绕过。

### P2：下载引擎、校验与清单

交付：

- 下载任务按 `queued → resolving → connecting → downloading → verifying → [bookmarking] → committing → completed` 发出事件，另有 skipped、failed、cancelled 终态；并发数默认 2，可配置范围为 1–3。
- 按错误类别执行有限重试：单次逻辑操作总计最多 3 次请求尝试，包含初次请求；镜像尝试计入同一预算，不产生重试叠乘。
- 实现临时文件写入、完成后原子发布、取消清理、失败结果记录和失败项重新下载。
- 获取平台文件大小和 MD5（存在时），下载后先验证原文件，再执行可选书签写入，最后计算最终文件 SHA256。
- 使用资源 ID、文件条目 ID、revision、本地路径、原文件 hash、最终文件 SHA256 等信息维护 `<output>/.textbook/manifest.sqlite3`，仅记录 completed 条目，支持校验后去重。
- 明确区分文件已发布与清单保存成功；清单写入失败必须可见，不能报告为已可靠登记。
- 由协调线程串行提交文件与 SQLite 事务；committing 临界区延后处理取消。每个工作线程使用独立 HTTP 会话。
- 使用 filelock 的平台原生锁对输出根目录施加单批次独占；第二个进程立即得到 `OUTPUT_BUSY`。首版只支持本地文件系统。
- 默认输出为 `./textbooks`，按学段/学科/版本分目录，缺失分类省略，安全文件名附短资源 ID。同名文件没有有效清单时报告冲突，只有显式 `--overwrite` 才替换。

完成门槛：

1. 本地 HTTP 服务验证流式下载、大小已知/未知、压缩响应、断流、超时、限速与错误分类，不依赖平台可用性。
2. 并发、重试预算和取消行为可重复验证；取消返回 130，完成的文件保留，未完成临时文件清理。
3. 传输校验失败不发布文件或记录 completed；书签失败则保留通过校验的原始 PDF，以 warning 完成并登记 `bookmarks_applied=false`。
4. 去重核对资源身份、版本与本地最终文件 hash；同名文件或仅文件存在不足以判定可跳过。revision 或平台 hash 缺失按架构定义的未知值策略处理，不能宣称已确认是最新版。
5. 同输出目录双进程互斥、不同目录独立；SQLite 事务故障后不会把未登记文件盲目认领，重跑遵循冲突策略。
6. 书签改写前后的 hash 分开记录；平台 MD5 只用于核对原文件，不能用于比较改写后的 PDF。

### P3：命令行与交互向导

交付：

- 接入 Typer 命令、prompt_toolkit 选书交互和 Rich 进度展示；具体界面及参数以 CLI 设计文档为准。
- 交互流程覆盖筛选、多选、粘贴教材链接、输出目录、书签选项（默认关闭）、下载结果及失败项重试。
- 所有界面消费核心事件，不在下载线程里直接绘制终端。
- 非 TTY 环境不自动启动交互；缺少必要输入时给出可脚本处理的错误。
- JSON 模式向 stdout 输出一个完整 JSON 对象，顶层为 `schema_version=1`、`command`、`ok`、`data`、`warnings`、`error`，下载逐项结果位于 `data.results`；进度及诊断写入 stderr，秘密不进入任一输出。

完成门槛：

1. 使用假平台适配器和本地 HTTP 服务完成选书到结果展示的端到端测试。
2. 退出码覆盖：0 成功、1 失败、2 输入错误、3 凭据问题、4 部分成功、130 取消；持久导入时 keyring 不可用属于退出 1，临时凭据文件非法属于退出 2，网络认证失败属于退出 3。
3. 终端缩放、中文长标题、多选和返回操作不会丢失选择或启动重复任务。
4. 关闭颜色、输出重定向及非 TTY 模式行为明确，JSON 可整体解析且没有混入进度文本。
5. 向导和非交互命令遵循同一下载、校验与去重规则。

### P4：跨平台发布准备与验收

交付：

- 形成可安装的软件包、依赖锁定记录、安装/升级/卸载说明和凭据使用说明。
- 在 Windows、macOS、Linux 上完成 Python 3.10 及选定较新 Python 版本的安装与运行验证。
- 验证中文路径、空格、长文件名、权限错误、keyring 差异、终端中断和无图形显示环境。
- 使用专门的人工在线检查核对当前平台目录和少量教材的下载链路；真实凭据仅由有权使用的测试者在本机提供。
- 建立平台接口变化的排查说明、已知限制和回归用例维护方式。

完成门槛：

1. 三平台离线与本地 HTTP 验收通过，安装包不要求图形界面组件。
2. 在有效用户凭据下完成至少一本教材下载，核对平台可提供的大小/MD5 并记录缺失项；MD5 匹配与不匹配必须另由本地测试覆盖。验证可选书签的最终 PDF 与清单 hash 一致。
3. 无效或过期凭据、目录不可用、网络中断和取消均有正确输出与退出码。
4. 如果真实凭据验证尚未完成，交付状态必须标为“离线验收完成，真实下载待验证”，不能报告全面验收。
5. 发布说明列出版本、适配平台时间、已验证范围和未验证限制。

## 3. 风险与处理顺序

| 风险 | 实现时处理 | 验收证据 |
| --- | --- | --- |
| 平台接口或字段改变 | 将变化限制在适配器；维护脱敏契约样本 | 样本回归与人工在线检查 |
| 私有资源鉴权变化 | 使用用户凭据动态签名，错误分类明确 | 签名单测与有效凭据下载记录 |
| 目录刷新中断 | 原子替换缓存，保留旧缓存及时间 | 缓存故障注入测试 |
| 下载成功但登记失败 | 单独报告清单错误，不删除已完成文件 | 文件/清单写入故障测试 |
| 同名教材或教材更新 | 以资源身份和 hash 去重 | 同名、不同 revision、文件被修改的回归测试 |
| 凭据存储不可用 | 明确提示 keyring 错误，不静默降级 | 三平台存储验证 |

## 4. 后续迭代边界

首版通过验收后，再分别评估 Range 续传、跨次任务恢复、配套音频与课程资源。自动登录与凭据刷新需先确认平台提供的可用流程，再决定是否纳入；不得将现有占位认证路径当作长期稳定能力。
